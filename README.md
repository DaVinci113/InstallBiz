# InstallBiz — сервис скачивания и анализа файлов

Сервис скачивает каталог текстовых файлов через внешнее API (порциями, с обработкой
ограничения частоты) и считает статистику по содержимому: сколько раз каждая цифра
0–9 встречается в выбранных файлах.

## Стек
- **FastAPI** + **Jinja2** (шаблоны) + ванильный JS/CSS (без сборки)
- **SQLAlchemy 2 (async)** + **asyncpg** (PostgreSQL)
- **aiohttp** — клиент к внешнему API (таймауты/Retry-After)
- **uv** для управления зависимостями

## Запуск

PostgreSQL и приложение описаны в `docker-compose.yml`. Локально (Postgres уже запущен на `localhost:5432`):

```bash
uv sync                       # установка зависимостей
uv run uvicorn main:app --reload --port 8000
```

Затем открыть http://127.0.0.1:8000

При первом старте таблица `files` создаётся автоматически (`Base.metadata.create_all`
в lifespan). Схема: `id, file_name (UNIQUE), downloaded_at (tz), content`.

## Страницы

### 1. `/` — страница скачивания
- Кнопка **«Скачать данные»** запускает фоновую задачу.
- Визуализация: время старта по Новосибирску (НСК, UTC+7), число полученных имён,
  «скачано M из N», число циклов, прогресс-бар, текущее сообщение.
- Корректно обрабатывает `429 Too Many Requests` и `403` (бан 30 мин): показывает
  паузу/таймер до разблокировки, после неё автоматически продолжает.
- Скачивание идёт, пока ручка `/api/files/names` не вернёт пустой список — это и есть
  признак полностью скачанного каталога.

### 2. `/files` — скачанные файлы и расчёты
- Таблица файлов: имя + время скачивания (НСК), сортировка по времени (asc/desc),
  пагинация.
- Выбор: несколько точечно, «все на странице», «вообще все файлы».
- Кнопка **«Произвести расчёты»** → частота цифр 0–9:
  - общая статистика по всем выбранным файлам;
  - статистика по каждому файлу.

## API сервиса

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/` | Страница скачивания |
| GET | `/files` | Страница файлов и расчётов |
| GET | `/download/status` | Статус фоновой задачи (для polling) |
| POST | `/download/start` | Запустить скачивание (идемпотентно, 202) |
| GET | `/files/list?order=&page=&size=` | Постраничный список файлов |
| POST | `/files/calc` | Расчёт статистики по выбранным файлам `{all, ids}` |

## Как устроено скачивание (`downloader.py` + `services.py`)

`DownloadManager` — синглтон, хранящий состояние и запускающий `asyncio`-задачу.

Цикл:
1. `GET /api/files/names` → порция имён (3–9). Пустой список → каталог скачан → `done`.
2. Скачивание батчами по 3: `POST /api/files/download` → ZIP. Архив **временно пишется
   в `data/`**, распаковывается, текст (500 цифр) сохраняется в БД (`content`),
   временный файл удаляется.
3. `POST /api/files/downloaded` — отметка, чтобы файлы больше не выдавались.

Между запросами — небольшой throttle, чтобы не ловить лимиты. При `429` сервис читает
`Retry-After`, ставит статус `throttled` и повторяет. При `403` — статус `blocked` с
таймером разблокировки и остановкой.

Идентификация — фиксированный заголовок `X-Candidate-Id` (прогресс предсказуем).

## Структура

```
main.py                 # FastAPI app, lifespan (БД + aiohttp-сессия), static
downloader.py           # DownloadManager — фоновая задача + статус
services.py             # низкоуровневый клиент внешнего API (429/403/Retry-After)
api/app_router.py       # HTML-страницы + REST-эндпоинты
database/
  models.py             # StoredFileModel (file_name UNIQUE, content)
  schemas.py            # Pydantic-схемы (страницы/расчёт/статус)
  services.py           # upsert, пагинация, расчёт, count
  db.py                 # engine, сессии
templates/
  base.html             # каркас + навигация + CSS
  index.html            # страница скачивания
  files.html            # список файлов и расчёты
```
